# Чат с анализом тональности сообщений

Курсовой проект по дисциплине «Программирование сетевых приложений». Централизованный сервер принимает сообщения пользователей, определяет их тональность готовой моделью RuBERT, сохраняет историю и рассчитывает статистику.

Репозиторий содержит исходный код и инструкции запуска. Чтобы поработать с приложением, его нужно скачать и запустить на компьютере: GitHub сам по себе не запускает Python-сервер этого проекта.

## Возможности

- регистрация, вход и сохранение учётных записей;
- общий чат и несколько отдельных личных диалогов с одним собеседником;
- история переписки, непрочитанные сообщения и выгрузка диалога в TXT или CSV;
- автоматическая оценка позитивной, нейтральной и негативной тональности сообщений;
- отдельный анализ текста без отправки в чат;
- фоновая обработка TXT, CSV и JSON с прогрессом и скачиванием результатов;
- статистика выбранного файла, круговые диаграммы и график активности чата;
- профили пользователей по накопленным результатам;
- очистка общего чата и удаление участников администратором;
- работа на компьютере и телефоне через браузер.

## Быстрый запуск в Windows

Требуется **Python 3.12 x64**. Для первой установки нужен интернет; после загрузки зависимостей и модели локальный анализ работает без внешнего API.

1. Нажмите **Code → Download ZIP** и распакуйте архив в обычную папку.
2. Запустите **setup.bat**. Скрипт создаст виртуальное окружение, установит зависимости и скачает модель размером около 47 МБ. Дождитесь сообщения о завершении.
3. Запустите **start.bat**. Откроется браузер с адресом `http://127.0.0.1:8000`.
4. Создайте аккаунт. В новой пустой базе первый зарегистрированный пользователь получает права администратора.

Окно сервера должно оставаться открытым. Для остановки используйте **stop.bat** либо `Ctrl+C` в окне сервера.

Для демонстрации с отдельными готовыми данными после установки запустите **demo.bat**. Он создаёт аккаунты **Александр**, **Мария** и **Дмитрий** с демонстрационным паролем **demo2026**. Эти данные создаются локально скриптом; рабочие базы и переписки в репозиторий не включены.

## Запуск в Visual Studio Code

Откройте распакованную папку проекта. Во встроенном терминале выполните:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe scripts\download_model.py
.\.venv\Scripts\python.exe main.py
```

Для запуска через F5 установите расширения Microsoft Python и Python Debugger и выберите интерпретатор `.venv\Scripts\python.exe`. Конфигурация запуска находится в `.vscode`.

## Подключение других устройств

- **Одна локальная сеть:** запустите `start_network.bat`. На втором устройстве откройте сетевой адрес, показанный сервером или в окне «Ссылка на чат». Python на клиентском устройстве не нужен.
- **Разные сети:** сначала выполните `setup_internet.bat`, затем `start_internet.bat`. Кнопка «Ссылка на чат» покажет временный HTTPS-адрес. После перезапуска туннеля ссылка может измениться.

Серверный компьютер должен быть включён. Адрес `127.0.0.1` работает только на самом серверном компьютере. Подробности – в [инструкции сетевого доступа](INTERNET.md).

## Проверка функций

1. Откройте два разных браузера и войдите под разными аккаунтами.
2. Отправьте сообщение в общий чат и проверьте доставку и метку тональности.
3. Создайте личный диалог, вернитесь к нему через список переписок и создайте второй с тем же собеседником.
4. Проверьте отдельную фразу в разделе «Анализ текста».
5. Загрузите [файл на 200 комментариев](samples/Проверка_статистики_200.csv) в разделе «Файлы». После обработки откроются его статистика и результаты.
6. Посмотрите диаграммы в разделе «Статистика» и профили участников.

В демонстрационном файле повторяются 30 разных фраз. Он предназначен для проверки загрузки, разметки и подсчётов; независимым корпусом для измерения точности модели не является. Столбец `expected_label` не управляет ответом модели.

## Как устроено приложение

Браузерный клиент написан на HTML, CSS и JavaScript. Сервер использует Python, FastAPI и Uvicorn. Сообщения передаются по WebSocket, файлы и обычные запросы – по HTTP. ONNX Runtime выполняет модель локально на процессоре. Вычисления вынесены в пул рабочих потоков; файлы обрабатываются порциями по восемь комментариев. SQLite хранит пользователей, сеансы, диалоги и результаты.

| Файл | Назначение |
|---|---|
| `main.py` | запуск сервера и выбор режима доступа |
| `app/server.py` | HTTP API и WebSocket |
| `app/sentiment.py` | токенизация и применение модели |
| `app/batch.py` | разбор файлов и очередь фоновой обработки |
| `app/connections.py` | соединения и рассылка событий |
| `app/storage.py` | база данных, авторизация, история и статистика |
| `app/access.py` | локальные адреса и временный HTTPS-туннель |
| `static/` | интерфейс, графики и звёздный фон |
| `tests/` | автоматические проверки |
| `samples/` | примеры входных файлов |

Модель – [cointegrated/rubert-tiny-sentiment-balanced](https://huggingface.co/cointegrated/rubert-tiny-sentiment-balanced); используется фиксированная [ONNX-версия](https://huggingface.co/onnx-community/rubert-tiny-sentiment-balanced-ONNX). Файл весов скачивается скриптом при установке. Веса не включены в Git-историю. Модель применяется готовой, её обучение в проекте не выполняется.

Класс выбирается по максимальной оценке. Оценки трёх классов не обязаны суммироваться в единицу и не являются измеренной точностью. Модель может ошибаться на иронии и текстах без контекста.

## Данные и ограничения

- файлы загружаются в UTF-8: до 1 МиБ, 1000 комментариев, 2000 символов на комментарий;
- в CSV требуется столбец `text`; в TXT каждый комментарий занимает строку; JSON содержит массив строк или объектов с полем `text`;
- статистика чата учитывает общий и личные диалоги; файловые комментарии считаются отдельно;
- профиль учитывает сообщения учётной записи и её завершённые загрузки: до пяти записей данных недостаточно, при доле класса от 60 % он считается преобладающим;
- профиль описывает набор текстов, включая загруженные комментарии, и не является психологической оценкой человека;
- история личного диалога доступна его участникам, результаты файла – его владельцу;
- удаление участника закрывает его доступ, сохраняя прежние сообщения; очистка общего чата не затрагивает личные диалоги и файлы;
- приложение рассчитано на учебную демонстрацию с одним серверным процессом.

Локальные данные создаются в `data/`, демонстрационные – в `demo_data/`. Эти папки, пароли пользователей, сеансы, журналы и резервные копии не публикуются.

## Тестирование

После установки запустите `run_tests.bat` или выполните:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

При установленном Node.js календарные расчёты графиков проверяются отдельно:

```powershell
node --test tests/test_charts.js
```

Подробнее об автоматических и интеграционных проверках – в [описании тестирования](docs/TESTING.md).
